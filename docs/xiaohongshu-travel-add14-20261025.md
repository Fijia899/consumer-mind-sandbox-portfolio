## 日期、隐私与解释边界

- 每条来源保存采集日、页面显示日期、原始定位链接及核查说明。只有页面明确显示年份时才填写 `published_at`；不根据帖子编号猜年份。相对日期保留“昨天”等原样并附采集日。
- 46 个情境全部为历史或时间未确认，没有一条冒充当前计划。乐崽同一帖子中的后续改期回复与原帖放在同一情境，防止只取较早愿望。momo 的独行、家庭游、住宿与旅拍分别保存。奶油小林的雨天帖月份和页面日期不能直接对应，明确保留不确定性。
- 情境是证据隔离的单位，不等于 46 次独立旅行；同一次旅行的不同记录可能分别保存。每个情境都有只引用本情境原话的研究追问和核对词，避免跨旅行汇总标签在预测时失去依据。个别补充情境仅有一项原话，仍由系统返回证据不足，不因整份档案已采纳就跳过这一限制。
- 只收录本研究所需旅游内容。未补写年龄、收入、性格、预算、职业、健康等人物属性；不收录家人健康、私下联系方式或对他人的贬损。部分作者公开自称创作者，仅作为来源偏差提示，不推断财务能力。
- 同一账号的多篇自述只能证明表达连续性，不是第三方独立验证；现实身份、一人一号、旅行是否实际发生、是否有商业合作均未核实。无法保证原帖完全未使用写作辅助，不能把“真实账号来源”误解为对原文创作过程的认证。
- 这是按相关性和材料丰富程度筛出的便利样本，创作者和经常公开表达者更易入选。不能由 14/49 或 20 份档案推算市场比例，不能把愿意了解解释为会付款。
- 每个页面只保存必要短引文，总计不超过 50 个字符，省略处用 `[…]` 标记；上下文以核查说明概括。未保存整篇原文。链接可能要求登录或失效，原文可能修改或删除，账号路径、笔记 ID 和评论 ID 有助于追查，但不等于完整网页存档。

## 入库与可回滚方式

可从沙盘的 JSON 文件入口导入本批文件，或者将 JSON 原样提交到 `POST /api/participants/import`。先进入待核查，再按来源核查记录逐个采纳为 `account_traceable`；未执行身份认证。相同内容重复导入应返回 14 个重复项，不新增档案，也不覆盖原有 6 份。

正式写入前保存 `data/participants_state.json` 的原始备份到被 Git 忽略的 `data/legacy_archive/before-add14-20261025/`。活动数据文件按项目设计不纳入 Git；可复现的来源批次、核查文档和测试纳入本次提交。回滚正式数据时先停止写入服务，再使用该目录中的原始备份恢复。
