# 可溯源真人档案与方案预测

> 历史研究或实施记录：本页保留当时范围与验证结果。当前操作、页面和测试命令请以[项目 README](../README.md)及[文档索引](README.md)为准。

本版数据关系是：**来源记录 → 真实来源用户档案 → 独立旅行情境 → 冻结方案预测 → 本人反馈**。

## 录入与采纳

页面手动表单适合一份问卷或访谈；网络样本需要多篇本人资料时使用 JSON 导入。CSV 模板在页面下载，每行一位受访者，包含以下列：

| 字段 | 内容 |
| --- | --- |
| `respondent_key` | 在同渠道保持稳定的匿名编号 |
| `platform` | 问卷项目/渠道名称 |
| `label` | 研究标签，不补造姓名 |
| `record_locator` | 可定位此人的原始答卷位置；本地文件须标明行号/答卷编号，不能所有人共用模糊地址 |
| `instrument_version` | 问卷版本 |
| `collected_at` | 采集日期 `YYYY-MM-DD` |
| `response_text` | 原始回答；只收集本研究所需信息 |
| `quotes` | 每行一项逐字自述，按 CSV 规则放在带引号的单元格中 |
| `episode_title` | 该次旅行情境 |
| `usage_basis` | 已获授权时填写 `consented` |
| `reviewer`、`review_note` | 来源核查人及说明；未填写则来源待核查 |

CSV 导入情境默认未确认当前有效。当前计划的确认日期、有效期与本人原话，用手动表单或 JSON 明确填写。JSON 接受 `{"records": [...]}` 或记录数组。完整字段由 `GET /api/participants/template` 返回的 Schema 给出；模板只有空数组，不提供虚构人物种子。每批 1–50 人，文件最多 5MB。

JSON 每个人包含 `subject_key/platform/label/profile_url/sources/facts/insights/episodes/limitations/unknowns`。

- `sources` 保存原始记录、定位、作者/编号、日期、授权依据、核查人和核查方式。问卷和访谈必须保留版本与授权依据。
- `facts` 只有 `id/source_id/quote`，引用必须逐字存在。模型推断、研究者标签不能作为事实来源。重复引文不能凑够采纳门槛。
- `insights` 保存研究者整理的需求、待确认问题、事实引用和核对词；标注人工或辅助整理。
- `episodes` 引用对应来源。一个人可以有多个旅行情境，各自使用自己的资料。当前情境还需本人确认原话、确认日期与有效期。

导入后先待核查。至少四项不同的已核查旅行自述、明确情境是初筛条件；纯网络记录还需两篇不同本人笔记及账号主页。问卷/访谈不机械要求两篇网络笔记。四项门槛不是统计学充分性的证明，审核人必须判断是否与研究目标有关。尚未核查的来源不进入预测。

同平台同编号为同一档案，重复内容不重复新增；修改导入会增加版本并回到待核查。已迁移档案与最终测试档案不可用导入覆盖。不同渠道不会自动关联；不同账号/答卷不能拼成一人。身份已核验必须另有核验记录，系统仅保存研究者的核验声明。

## 预测与失败处理

每次预测选择档案、情境、方案、`source_context/current` 和 `development/holdout`。先持久化输入快照、档案版本、模型名称、引擎代码指纹和时间，再发起模型请求。来源中的指令只当作待分析的数据；模型只收到所选情境的已核查自述、明确标注的分析和日期信息，不收到账号 ID、主页链接或反馈记录。文本中常见电话和邮箱会被遮蔽，录入时仍应去除无关个人信息。

三组结果：无个人资料的通用模型、固定简单规则、真人证据模型。简单规则只核对方案是否触及研究者记录的主题；匹配后保守标为犹豫，否则证据不足，不把提及当作履约证明。它是预先固定的基线，未拟合成预测器。

模型输出限定类别、事实编号、方案原文片段和缺失问题。支持与反向事实均须属于所选情境；推进或拒绝必须有方案原文对应。解释由服务端用第三人称模板呈现，不让模型补写人物经历。无决定性依据应返回证据不足；不适用需要明确的无出行/取消计划自述。

所选情境少于两项不同自述，或要求当前计划但缺少/过期确认时，三个方法均记为证据不足，模型不运行；页面明确记录原因。模型请求或输出校验失败时整组失败，不显示部分成功或规则回退结果。服务重启会把遗留处理中记录标为中断失败。失败记录保留供排查，允许重试；同一人、同一情境与预测范围、同一完成方案不能重复运行挑选结果。

## 本人验证与指标

1. 首次预测锁定参与者属于开发组或最终测试组，不允许之后切换。最终测试资料与采纳状态冻结。
2. 先完成冻结预测，再向该人展示同一情境与方案。本人此前资料可作输入；本次答案不得事先泄漏。不要把模型判断展示给本人。
3. 使用同一账号 ID/匿名编号登记实际作答时间、意向、原话、原始记录位置、对应关系核查与授权。系统匹配编号和时间，但无法自动证明提交者现实身份。
4. 反馈不可覆盖；不能复用基线来源或已知输入原话作为后续答案；已登记反馈不能再导回基线。最终测试人员答案揭示后不能再用于新的最终测试。开发答案用于调试时必须保留开发组标记。

指标按用途分组、引擎指纹、模型、当前/条件预测范围分别统计，每个案例的三组方法用同一份本人反馈比较。记录总请求数、完成/失败/处理中、独立参与者数与反馈者数。

- 覆盖率：有类别判断的完成结果 / 全部请求；证据不足率：完成且不足的结果 / 全部请求。失败与处理中另计，不能隐藏故障后只报告易预测样本。
- 有判断时一致率：命中 / 有判断且已反馈的案例。
- 全部反馈命中率：命中 / 所有完成且已反馈案例，证据不足也留在分母。
- 四类 Macro F1：固定四个真人意向类别的 F1 均值；证据不足计作对应真实类别的漏判，无样本类别为 0。少量或类别不全的样本不宜解读该单一数值。
- 混淆表：真实四类 × 预测五类，直接显示各类错判与拒答。

没有反馈时准确率和 F1 为未知。重复方案可产生多个案例，因此同时报告独立人数；不据此推算市场比例。编号校验、原文校验不能发现所有语义泄漏，研究者仍需保证独立招募、真实记录及前瞻时序。

## 迁移与恢复

首次初始化先备份原始文件，再迁入已有 6 个账号来源样本。旧原文件不改写；备份以 SHA-256 验证，归档页只有查看功能。迁入数据保留已核对摘要、短引文和核查方式，不宣称取得完整原始笔记，也不升级为身份已核验。

`data/participants_state.json` 是本地新研究台账，`data/legacy_archive/<id>/manifest.json` 是原始备份清单。备份这些本地文件以便恢复；停止服务后再做文件级恢复。Git 保存代码和已公开整理资料，不包含新问卷/访谈原文、本人反馈或迁移备份。已有未提交资料保持原字节，不随本次代码提交。

旧模块保留用于历史数据兼容回归。旧公开写入接口全部停用，不再生成合成人物或把真实评论附加到合成人物上。旧校准文档仅用于解释历史归档。
