# 小红书旅游意向公开样本核查

> 历史研究或实施记录：本页保留当时范围与验证结果。当前操作、页面和测试命令请以[项目 README](../README.md)及[文档索引](README.md)为准。

核查日：2026-10-24。20 个账号完成评论 → 主页追溯，6 个采纳，14 个排除。结果保存在 `data/xiaohongshu_travel_profiles.json`，沙盘首页“**小红书公开旅行需求样本**”直接展示。未把信息不足的账号扩写成人物，也未将 6 个样本写成 20 个可用画像。

## 来源与方法

研究结构参考 [Customer-Mind-JTBD-Sandbox](https://github.com/yiqiyao13/Customer-Mind-JTBD-Sandbox)：先保留任务情境、明确自述、阻碍和期望，再整理可追问的需求。2026-10-24 核对远端 HEAD/main 均为 `7747517a36ccd92fb4a5c68866bc565ab18329c1`，与项目所用参考版本一致，没有新增变更需要同步。

从“想旅游却找不到同伴”“低开销目的地”“和父母出游”三个公开讨论，选择可见的旅行愿望、顾虑或经验评论，依次进入该评论者主页。核查主页首批约 30 篇可见内容（含置顶）或当次已加载内容，再打开相关本人笔记，核对笔记作者主页 ID。没有穷尽账号历史，没有读取私信、私密内容或收藏，也未据视频或图片中的细节作判断。用户登录后，在后台内置浏览器读取页面，没有操作用户看电视的桌面或向账号发送消息。

采纳须满足：入口评论与主页、笔记作者的账号 ID 一致；入口评论外，至少两篇不同的本人旅行笔记参与事实支持；至少四项具体旅行自述；人工复查日期、情境、矛盾和缺失。篇数只是最低门槛，多条极简内容不自动等于充分信息。排除只描述本次可见材料不足，不声称该人没有其他旅行经历。

采纳样本共保留 **24 条来源记录**：6 条入口评论、18 篇本人笔记；入口评论分布在 3 个讨论，因此共 **21 个不同笔记页面**。33 项自述有逐项来源引用；18 个需求标签和追问明确标为研究者整理。少数短笔记仅作补充，不承担完整行程或预算推断。原始链接、规范链接、页面日期、核查日期、短引文及评论 ID 保存在数据文件中；未保存整篇原文、其他日常内容或无关个人信息。

## 采纳结果

| 样本 | 可用于核对的旅行需求 | 必须保留的边界 |
| --- | --- | --- |
| XHS-05 | 短假独行准备、休息余量、与朋友的主题乐园拍照便利 | 独行与朋友出游是不同计划；北京短笔记不证明独行已完成 |
| XHS-07 | 同行时间确认、路线与出境准备、共同体验当地生活 | 蚌埠和韩国情境分开；历史通关等候不是当前规定 |
| XHS-09 | 公交资料时效、人流与住宿确定性、赏秋窗口和费用口径 | 武威旧开销不含大交通，不能变成当前人均总预算 |
| XHS-10 | 工作日同行匹配、接驳与行李时间余量、体验与安全信息 | 安全表述是个人顾虑；江西游记不等于当下一日游安排 |
| XHS-12 | 亲子活动与休息、住宿可订性和隔音、预约与餐饮 | 不推断孩子当前年龄或偏好；旧设施与商业合作未经独立核实 |
| XHS-17 | 家庭出游可退预订、行程强度、开放时间与备选路线 | 同时存在慢游和紧凑安排，不能贴“总是慢游”的人格标签 |

每个样本有 4 条来源记录与 5–6 项具体自述。主页、笔记、完整筛选台账和逐条排除理由可在沙盘展开查看；数据文件的 `screening` 包含全部 20 个账号。主要排除原因是没有可见的独立旅行笔记、只有一篇相关笔记、同一讨论的重复回复，或虽然有多篇但文本过短、情境过旧而无法形成充分支持。

## 在沙盘中使用

1. 在公开样本卡片勾选希望参考的样本。
2. 在“测试旅行方案或营销话术”填写方案，点击“用公开样本核对”。
3. 结果列出“方案提及 · 待核实”或“未检出相关表述”，同时保留来源和追问。点击 `[C1]` / `[N1]` 可定位到证据。

核对仅按明确关键词定位主题，可能漏掉同义表达；不进行语义满足判断。“可退款”和“不可退款”都会涉及退改主题，均不会被标成已解决。编辑方案或更改选择后，旧核对结果失效。没有给公开样本生成意愿分、购买概率或第一人称预测，也未写入合成画像、校准数据或独立验证集。已有合成画像测试入口继续作为演练工具。

## 解释范围

这是三个讨论下的目的性便利样本，受搜索排序、可见内容和公开表达习惯影响。6/20 是本批采纳数，不是市场占比或对总体的估计。同一作者多篇自述并非第三方独立验证；站内账号对应也不证明真实身份、旅行真实性或无商业合作。

发布时间与旅行时间不混同。没有年份的日期保持原样，“昨天”等相对日期附核查日。历史计划不会自动延续为当前购买意向，未知的年龄、收入、职业、预算、人数、预订状态都不补造。链接可能需要登录、签名可能失效、原文可能删除；保留规范链接和评论 ID 辅助复查，但短引文与摘要不构成完整网页档案。

## 验证方式

`tests/test_observed_profiles.py` 检查采纳与排除集合、账号归属、跨账号引用、独立笔记门槛、未知字段与日期、请求边界、否定表述和数据不被改写。`tests/observed_profiles_browser.cjs` 在隔离服务和无界面浏览器检查来源定位、20 人台账、选择、错误提示、过期结果清除、文本转义和手机布局。交付前还运行全量 Python 测试及已有旅行、研究页面回归测试。

本次验证结果：`python -m pytest -q` 为 **113 passed**；公开样本、旅行工作台、研究页三套浏览器回归全部通过；4 个前端脚本的 `node --check` 和 `git diff --check` 通过。Python 测试仍有 3 条既有依赖弃用提示。8000 端口正式服务重启后，后台浏览器确认 6 张采纳卡片、20 个核查账号和来源计数正确展示。测试前后现有 `data/personas.json` 字节一致。
