## 操作流程

1. 打开工作台导航中的“研究校准”。可以载入 6 条公开语料起步包，也可以手动录入、上传 JSON 或 CSV。
2. 每条新资料都是“待审核”。核对原文、上下文、主要任务、旅行阶段、发言视角、维度标签与引文。初步标签可以修改或移除。记录审核人、审核方式与说明；疑似营销/虚假资料不能通过。
3. 明确区分直接表达、研究者推断。旅行属性也区分明确自述和推断。只有直接表达与明确自述会进入画像校准；未知属性不补成真人事实。
4. 创建版本，仅使用已通过的调整集。返回工作台，勾选“使用已审核评论校准”，可另选是否纳入自述旅行属性。没有有效版本时，不能启用证据模式。
5. 查看每张画像的证据来源、被校准字段与合成边界。姓名、年龄、职业等未关联来源的细节仍是合成示例。记录本身不是完整的真人画像。
6. 使用留出评论检查维度识别误差；使用独立真人实验检查意向判断。两个结果分开展示。

## 数据与审核

JSON 接收 `{"records": [...]}` 或记录数组，字段可参照页面的“下载 JSON 示例”。CSV 使用相同列名，`labels` 和 `profile` 列填写 JSON 数组。每批最多 500 条、文件最多 5MB，整批校验成功才保存。研究导出用于归档阅读，不是直接恢复本地分组盐的备份格式。

最小记录示例（此段是格式演示，不是真实研究证据）：

```json
{
  "source_url": "https://example.com/travel/1",
  "platform": "授权访谈",
  "author_key": "participant-001",
  "usage_basis": "consented",
  "text": "这次旅行我的人均预算是2000元，担心总花费超预算。",
  "job_id": "J3",
  "stage": "比价决策",
  "labels": [{
    "factor_id": "B1",
    "quote": "担心总花费超预算",
    "terms": ["超预算"],
    "basis": "explicit"
  }],
  "profile": [{
    "field": "budget_per_person",
    "value": 2000,
    "quote": "我的人均预算是2000元",
    "basis": "self_report"
  }]
}
```

属性限定为出发时间、旅行天数、同行人数、人民币人均预算、是否预订、同行安排描述。数字须经审核人确认原文明示的单位与含义；例如美元总预算不能直接填写为人民币人均预算，10–14 天不能自行挑成 12 天。自述可能有误，也可能只适用于当时一次旅行。

审核通过表示资料标注已核对，不表示已验证账号背后的身份或真实经历。人工核对和模型辅助整理分别记录；辅助整理的标签仍需要独立人工复核，尤其不能用同一个模型的标注结果证明模型真实性。

导入会基础移除邮箱、常见大陆手机号与 @账号；这不是完整的匿名化工具。导入前仍应人工去除不必要的个人信息，仅保留研究需要的内容。来源链接保留以便追溯，可能仍能关联公开账号。平台作者代号只在本地加盐散列，不保存明文；同平台同作者必须始终使用同一代号，不得跨平台猜测并拼接身份。

## 数据集隔离与版本

按匿名作者散列稳定分组，约 20% 分配到留出集。作者未知时以来源 URL 分组，明确显示“来源分组，作者未知”。同一讨论来源也固定在同一组；同一作者在不同来源的记录保持同组。导入若发现作者和来源连接了已有两个不同分区，会整批拒绝，需整理重复来源后重导。

标准化后的相同原文会去重；近似改写、跨平台转载、同一人更换账号仍需要人工识别。未识别的账号关联会造成潜在泄漏，所以“按来源隔离”不能表述为“真人身份已核实的独立样本”。小样本可能没有留出资料，此时系统明确提示缺少资料，不生成准确率。

校准版本冻结证据 ID、修订号、检索词、来源分布、独立组计数、标注方式和研究引擎/数据配置指纹。修改该版本使用的证据，或改变任务、维度、结果、蓝图、引擎代码，会使当前版本失效。版本使用过的证据被删除时，关联版本、留出报告和实验记录一并移除。既有画像和导出的文件需要另行移除或重新生成。

画像生成只检索调整集、审核通过、计划本次旅行、与任务/步骤兼容的资料。一张画像以一条来源校准，避免把不同人的旅行预算和同行安排拼成同一人的自述。旅行日期按历史原文保留，不自动改成当前时间。若没有匹配资料，继续显示“无匹配证据”，不得虚构来源。LLM 不能改写证据引用、校准字段或把留出资料带入生成提示词。

当前关注强度与重要性使用固定规则；评论频次不自动转成市场人群权重。新增维度、改写任务本体仍需要研究者判断，不会因出现一次新词自动改写全局模型。

## 两种验证

### 在话术结果卡核对真人反馈

工作台每次成功运行话术测试后，会在本地研究库保存当次话术、画像快照、实际展示的规则或模型反馈和引擎指纹。展开结果卡的“待真人验证”，在向真人展示话术前填写招募渠道、匿名参与者代号和旅行情境匹配说明。登记引用服务端冻结结果，不接受浏览器改写预测，也不会重跑模型。更换当前画像后，原快照仍可用于对照。

在工作台“真人反馈与预测对照”登记真人意向、原话、记录人和可回查的证据出处。缺少出处不能提交；保存后不可覆盖。系统根据四类意向标签自动显示“一致 / 不一致”，尚无真人记录时显示“待真人验证”。这些标签说明研究者登记的意向是否与预测一致，不证明身份或证据已由系统核实，也不代表预订行为。

同一参与者在同一次话术测试中不能重复登记，评论证据库中的参与者不能加入独立验证。渠道和代号需要研究者保持一致，系统无法识别跨渠道或换代号的同一人。一致率按校准版本、引擎指纹及规则/模型模式分组，同时列出测试数与独立参与者数，与三组规则实验分开展示。验证记录不自动更新画像或注入后续模型记忆，避免将独立对照资料重新用于预测。删除来源证据会清理使用它的冻结测试及关联验证记录。

### 评论维度识别

原始规则使用现有维度关键词，校准方法增加调整集审核者指定的原文检索词。两种方法对同一批已审核留出原文作维度识别，与留出标签对照，报告精确率、召回率、Micro F1、标签完全匹配率及逐条漏识别/多识别。

报告记录来源分布、匿名组数、标注方式、数据修订号及同版本验证次数。留出标签或引擎变动后，旧报告显示历史结果已过时。查看留出误差后再针对它调参，会使它成为开发资料；最终结论需要另收独立资料复验。该报告不验证画像真实性、偏好比例、方案排序或实际预订。

### 真人意向反应

选择与画像情境匹配且未进入评论证据库的独立参与者。在测试前登记方案，系统冻结三种规则预测：原合成画像、评论校准、评论加明确自述旅行属性。研究者随后向真人展示相同方案，询问是否愿意进一步了解，再登记原话和结果。结果保存后不可覆盖。

匿名参与者代号可查出其是否已在评论库中；它不能自动证明研究者确实先登记再访谈，也不能识别换账号或换渠道的同一人。实验参与者不能随后再被导入为调整证据。冻结的预测与版本指纹保留，意向一致率按版本和引擎指纹汇总，同时显示测试次数与独立参与者数，避免把规则更新前后的实验混成一个结果。

原画像与评论校准版本的规则都可能使用合成预算；纳入明确自述后，预算属性能影响显式的人民币人均报价判断。三组预测可能相同，应如实记录，不能强行制造差异。

这些是自述意向的描述性对照，没有自动推算实际咨询/预订转化、统计显著性或市场准确率。尚无真人结果时显示“尚无真人实验”，系统不生成真人观测。
