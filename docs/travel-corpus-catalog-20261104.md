## 目的与边界

本文件整理项目当前已有的旅游研究材料，供后续语料分析和 Agent 证据检索使用。它不把不同来源集合并成一个统一样本，也不将主题标签或样本数量解释为旅游意向人群的市场比例。

研究结构参考 [Customer-Mind-JTBD-Sandbox](https://github.com/yiqiyao13/Customer-Mind-JTBD-Sandbox) 当前公开的 Job / Step / Outcome / Force 结构。上游公开规格把完整原始语料建为可检索证据库列为可选后续工作；本项目以下编目只依据本地已保存的旅游材料，不假定上游原始数据可检索。

## 初步主题地图

以下是基于现有 JTBD 结构和语料标签的**编目主题**，用于整理和检索，不是已经完成的主题饱和或人群需求排序结论。

| 主题 | 关联 Job | 语料中可见的研究问题 | 当前材料例子 / 编码线索 |
|---|---|---|---|
| 目的地与体验选择 | J1、J7 | 什么让目的地值得去；用户想获得何种体验；内容灵感如何转成计划 | 目的地期待、季节窗口、真实体验、拍照与便利之间的取舍。 |
| 同行协调 | J2 | 日期、同行方式和核心活动如何协调；独行与结伴是否属于不同旅行情境 | 同行时间难统一、旅行同伴对目的地数量或节奏有不同看法。 |
| 预算与比较负担 | J3 | 用户如何理解总花费；价格、便利、保障之间如何取舍 | “不想多个平台比来比去的，挺累的”是比价疲劳线索，不足以推断预算额度或购买倾向。 |
| 路线与旅行节奏 | J4 | 交通、活动、预约怎样衔接；行程是否过密；是否留出休息和备选空间 | 路线串联、跨点交通、预约衔接、体力与休息余量。 |
| 预订信任与服务保障 | J5 | 住宿、交通和服务是否可靠；退改、到店问题和售后责任如何影响预订 | 退改条件、住宿信息、服务责任及旅后处理经历。旅后投诉是当事人自述，不能当作独立责任认定。 |
| 出行准备与变化应对 | J6 | 哪些信息缺口会妨碍出发；如何应对天气、交通、证件、语言和临时变更 | 预约、交通衔接、语言准备、天气和备选方案。历史问题不自动等于当前风险。 |

主题之间允许交叉。例如“为了减少转车而改目的地”可能同时涉及目的地选择、路线规划和时间成本。编码应保留多个有证据支持的关联，不要求每条材料只落入一个 Job。

## 当前证据覆盖情况

- 16 条公开摘录目前映射到 7 个 Job；现有标签较多落在出行准备、比价决策和预订确认等阶段。小样本数量只能描述当前文件的编码覆盖，不能据此认定需求强弱或优先级。
- 20 个档案包含 70 个独立旅行情境，其中 48 个标记为历史、22 个时间范围未确认。分析当前计划时应优先使用当前确认材料；不得把历史旅行偏好自动延续为当前偏好。
- 档案的 157 项事实都关联来源 ID；研究洞察另行记录并引用事实 ID。分析报告需保留这层区分，不把研究者归纳改写成用户原话。
- 当前公开摘录有较细的 Job、Stage 和 Factor 标签；档案中的来源和事实关联更细，但旅行情境还没有统一的证据级 Outcome、Force、支持/反向/未知关系编码。因此后续不应只凭画像顶层标签推断每条事实支持了哪个 Outcome。
- 公开来源以目的性便利样本为主，平台可见性、作者自我表达和保存为短引文的方式都会影响主题覆盖。不能用账号、来源、摘录或档案数量计算市场份额。

## 建议的统一证据条目

新增分析数据时保留原文件不变，按“一个可定位的原话或核查摘要一条证据”建立索引，至少包含：

| 字段 | 内容 |
|---|---|
| `evidence_id` | 稳定 ID；能回指现有 source / fact ID。 |
| `source_id`、`source_url`、`source_date` | 来源定位和可核查日期；日期不明时保留未知。 |
| `subject_id`、`episode_id` | 可选匿名账号 ID 和单次旅行情境 ID；不跨情境合并。 |
| `representation` | `verbatim`、`checked_summary` 或其他明确的原始表示类型。 |
| `quote_or_summary`、`context` | 原文短引或已核查摘要及必要上下文；不扩写缺失内容。 |
| `basis` | 用户自述、研究者归纳、模型建议等来源性质。 |
| `job_ids`、`step_ids`、`outcome_ids`、`factor_ids` | 有依据时多选；不能判断时留空。 |
| `force`、`evidence_polarity` | 推动、吸引、焦虑阻力、习惯/替代；支持、反向、混合或未知，并附编码说明。 |
| `review_status`、`review_note` | 待核查、已核查或排除，以及审核边界。 |

后续 Agent 可按研究问题和旅行情境检索已审核条目，再生成带 `evidence_id` 的结论。模型建议标签应先进入待审核状态；没有足够语料时返回缺口，不补造画像或人群比例。

## 当前已知缺口

1. 尚未形成覆盖不同来源类型的统一证据索引；公开摘录与账号档案目前分文件管理。
2. 档案事实缺少逐条统一的 Outcome / Force 编码，不能安全地从 Job 或 Factor 标签自动推导。
3. 记录中的时间、计划/旅后视角、来源质量和商业关系需在跨来源比较时统一筛选规则。
4. 目前资料适合形成可追溯的定性假设，不足以验证总体占比、预测准确率或主题饱和度。

## 维护约定

新增语料时保留原始来源和核查边界；新编码记录审核状态、编码者/方法及依据。更新任一数据集合后，同步更新本清单中的规模和覆盖说明，并运行语料数据测试。
