## 现在的分析回路

提交个性化或通用方案分析时，服务端读取当前启用的决策维度，并将其完整快照与所选画像、方案和业务约束一同保存。停用维度不会进入本次任务。此后即使后台修改维度，已创建任务和同组方案对照仍使用原快照；新任务读取最新启用配置。

Agent 逐个画像需求分析方案，模型须对每项需求返回：

- 需求满足状态和解释；
- 方案中支持判断的逐字片段；
- 与该需求相关的启用决策维度、匹配理由及方案原文片段；
- 需要研究者确认的问题。

某需求没有可靠维度关联时返回空数组。模型不能引用快照之外的维度。服务端检查每项需求均有结果、维度 ID 属于快照中的启用维度、匹配引文逐字存在于本次方案，并拒绝重复维度关联。报告按维度汇总匹配到的需求数和画像数；没有匹配的启用维度也显示为 0。

修改建议会读取画像需求、维度匹配和当前启用维度快照。候选方案仍需在同一画像与维度快照上重新分析，才能查看修改前后差异。

## 权重与结果解释

维度权重（1–10）传给分析模型，提示研究关注优先级。它不是方案满足度分数、用户意愿分、市场权重或统计概率，也不直接累加成覆盖指标。报告的方案匹配和需求满足结论仍由模型语义判断产生。

自动校验只能确保结构完整、维度处于启用清单中、方案引文逐字有效；不能独立证明模型把某条方案内容关联到某个维度在语义上必然正确。研究者仍需检查维度理由和原文。

## 与旅游语料的关系

本次改动把现有决策维度管理接入 Agent 分析，并没有把 `data/travel_evidence_zh.json` 的公开摘录做成检索增强语料库。已采纳账号档案仍按原有方式提供画像和旅行情境。需要逐条引用公开摘录时，还需另建证据索引并把检索结果接入 Agent。

## 验证

- Python 全量测试覆盖启用维度快照、停用/未知维度拒绝、方案引文校验、维度匹配计数和同集合对照。
- 浏览器回归检查结果页的维度匹配、权重显示和报告交互；测试模型使用隔离夹具，不代表真实模型质量。
- 真实模型的语义匹配质量需在有效模型凭据下另行抽样审核。
